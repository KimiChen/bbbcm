## 关键设计

**幂等靠唯一键，不靠投递前先查**。Outbox 是「至少一次」语义,同一事件必然被投递多次，
多个 Worker 并行时还会同时投。先查再插在并发下必然漏——两路同时查到「还没有」就各插一条。

**重复投递不报错**。返回 `created = false`。若报错，Worker 会把成功的重试当成失败继续
重试下去，形成一个永远消不掉的队列项。

**未读用哨兵时间戳而非可空列**。可空列会让「未读」在 SQL 里变成 NULL 语义，
而三库对 NULL 的排序与比较差异正是 `DEC-022` 要避开的。与 community 侧 `deleted_at` 同一约定。

**`mark_read` 的条件含 `recipient_id`**。只用 id 的话，拿到别人的通知 ID 就能把它标为已读，
是一次典型的 ID 替换越权。测试正面断言他人无法标记。

**不给自己发通知**。自己回复自己的主题不该产生「有人回复了你」。

**不存未读计数**。冗余计数与已读状态一旦不一致，用户会看到「有未读但点进去是空的」，
那种 bug 极难复现。
