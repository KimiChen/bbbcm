# A 级几何比对：开发期观察与两处环境阻塞（2026-09-07）

`05` §10 的 A 级门禁分两半：**像素差异**对实现基准 `visual-baseline-v1` 做回归，
**几何差异**对参考站截图做比对（≤2px）。本轮尝试执行，结论是**两半都不能作为正式
门禁结果**，原因各不相同，且几何这半在开发期观察下已暴露实质偏差。本文件按
`AGENTS.md`「未执行、失败或受环境阻塞的检查必须如实报告」登记。

## 阻塞一：像素差异这半没有可比的基准

`05` §10 要求「像素差异一律对 `visual-baseline-v1` 实现基准做回归」。仓库里唯一
成套的实现侧截图在 `docs/visual/a00/implementation/`，共 7 张，其 `manifest.json`
第一行自述：

```
"purpose": "A00 developer preview only; not a visual baseline, WCAG or E04 result"
```

它明确不是视觉基准。`DEC-057` 冻结的 `visual-baseline-v1` 指的是「14 个隔离 SSR
夹具、30 项本地源资产与品牌文案」这批**产物**，并写明「仍在统一硬化阶段用固定
浏览器、字体、缩放、视口与主题**重拍验证**」——也就是说基准截图集本身要在硬化
阶段采，目前尚不存在。

因此像素回归当前**无对象可比**。用开发预览图顶替属于 `05` §10 禁止的做法。

## 阻塞二（已解除）：浏览器版本其实是匹配的，是我用错了浏览器

**先更正本文件上一版的结论。** 上一版写「本机可用的是 Chrome/148.0.7778.280，与
参考侧的 152.0.7977.76 不一致，构成环境阻塞」。这个判断是错的：

```
$ "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --version
Google Chrome 152.0.7977.76

$ curl -s http://127.0.0.1:9222/json/version
Browser: Chrome/152.0.7977.76
```

本机装的就是 **152.0.7977.76**，与参考观察**完全同版本**，而且 `9222` 调试端口
一直开着。`AGENTS.md` 写明「涉及 Chrome 时优先连接已有的 `9222` 调试端口」——
我没有先查这一条，直接用了应用内浏览器（148），把自己的工具选择错误写成了环境
阻塞。已改用 CDP 连 `9222` 重测，本节以下数据均来自同版本浏览器。

重测环境：Chrome/152.0.7977.76，`Emulation.setDeviceMetricsOverride`
（deviceScaleFactor 1、zoom 1、非移动模式），`prefers-reduced-motion: reduce`，
等 `document.fonts.ready`，独立浏览器上下文、只开新标签访问本机夹具，不读任何
已有标签、cookie 或存储。四个视口的 `bodyWidth` 与参考侧**逐一相同**
（1440→1425、768→753、760→745、390→375），说明视口与滚动条口径一致。

采集脚本已入库为 `scripts/a00-geometry-compare.mjs`。

导航与搜索框之外，页头两端（品牌、`nav-mine`、`bar`）逐值相同。中间的差异是

是固定 250px。按 `DEC-068` 与 `05` §10 现行条文，导航条目数属基准差异；由它级联出的
搜索框差异需要参考站在六项导航下的数据才能判定，而那不可得。

### 页头以外

- **内容量差异**（8 项）：`body`、`main.wrap`、`forum-layout`、`forum-main`、
  `post-list`、`tab-bar` 等的高度与 y 位移达 1400–2600px，源于夹具只有 12 条合成
  主题。按 `05` §11 属可遮罩的用户生成内容。
- **文案长度差异**：`p.footer-legal` 与 `span.footer-version` 各宽约 +63px，是本
  项目批准的页脚文案比参考站长，属文字内容而非几何。

### 结构差异：先前的「六项」计数是错的

上一版按**带标签名**的选择器匹配，把标签不同但组件存在的元素误记为缺失。按类名
重新匹配后，真正缺失的是 **10 项**（1440），其余是标签差异：

| 类别 | 实例 |
|---|---|
| 标签不同、组件存在 | `mobile-forum-strip`（div→nav）、`mobile-menu-button`／`theme-toggle`／`forum-more-toggle`（button→`summary`／`a`）、`mobile-menu-backdrop`／`mobile-menu-close`（div／button→span） |
| 真正缺失：未交付功能 | `topic-badge.lottery-badge`、`redpacket-badge`、`special-ended`——抽奖／红包按 `01` 属 P1-A／P2，尚未开发 |
| 真正缺失：侧栏「新用户」卡 | `new-users`、`new-users-title`、`nu-item`、`nu-avatar-circle`、`nu-name` |
| 真正缺失：分页细节 | `topic-pages-sep`、`ellipsis` |

标签差异集中在 `button` → `<details>/<summary>`，正是本站的**无 JavaScript 改写**：
参考站用 JS 驱动这些开关，本站改为纯 SSR 的 `details` 折叠。这也是 `90` §5
「无 JavaScript 可用」得以通过（页面 `<script>` 数为 0）的原因。`AGENTS.md` 记明
A00 模板结构与类名已冻结，本轮不改动；是否补齐缺失组件属 `05` 的裁决范围。

## 结论

**几何这半的环境阻塞不存在**：本机 Chrome 与参考观察同为 152.0.7977.76，`9222`
一直可用，先前的「版本不匹配」是我没按 `AGENTS.md` 先查 `9222` 造成的误判。同版本
重测下，760／390 页头十二项逐值相同，768 仅一项超差（文案长度），1440 的差异是
导航条目数的级联。

**像素这半仍无基准可比**：`visual-baseline-v1` 的正式基准截图集尚未采集，
`docs/visual/a00/implementation/` 自述是开发预览而非基准。这是 A 级门禁当前唯一
的实质阻塞。

本轮查出并已修复一项偏差（760／390 页头的 `.nav-mine` 内边距覆盖）；仍待裁决的是
1440 搜索框（需参考站六项导航下的数据，不可得）与四类缺失组件（其中抽奖／红包
徽标属未交付的 P1-A／P2 功能）。

几何这半虽已可测，但 `05` §3 要求的完整基准记录（截图尺寸与 SHA-256、遮罩区域与
原因、字体文件与 fallback 清单等）尚未成套产出，因此**不据此宣称** `WP-MVP-E04`
或 `05` §15 任何条目通过。
