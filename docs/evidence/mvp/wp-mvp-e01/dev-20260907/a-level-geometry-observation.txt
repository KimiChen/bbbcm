# A 级几何比对：开发期观察与两处环境阻塞（2026-09-07）

`05` §10 的 A 级门禁分两半：**像素差异**对实现基准 `visual-baseline-v1` 做回归，
**几何差异**对参考站截图做比对（≤2px）。本轮尝试执行，结论是**两半都不能作为正式
门禁结果**，原因各不相同，且几何这半在开发期观察下已暴露实质偏差。本文件按
`AGENTS.md`「未执行、失败或受环境阻塞的检查必须如实报告」登记。

## 阻塞一：像素差异这半没有可比的基准

`05` §10 要求「像素差异一律对 `visual-baseline-v1` 实现基准做回归」。仓库里唯一
成套的实现侧截图在 `docs/visual/a00/implementation/`，共 7 张，其 `manifest.json`
第一行自述：

```
"purpose": "A00 developer preview only; not a visual baseline, WCAG or E04 result"
```

它明确不是视觉基准。`DEC-057` 冻结的 `visual-baseline-v1` 指的是「14 个隔离 SSR
夹具、30 项本地源资产与品牌文案」这批**产物**，并写明「仍在统一硬化阶段用固定
浏览器、字体、缩放、视口与主题**重拍验证**」——也就是说基准截图集本身要在硬化
阶段采，目前尚不存在。

因此像素回归当前**无对象可比**。用开发预览图顶替属于 `05` §10 禁止的做法。

## 阻塞二：本机浏览器与参考观察不是同一版本

参考侧 computed JSON 由 **Chrome/152.0.7977.76** 采集（见
`docs/visual/a00/implementation/manifest.json` 与 `capture.md`）。本机当前可用的是
**Chrome/148.0.7778.280**。`05` §3 要求基准记录含「Chromium 精确版本」，§10 明确
「禁止通过……改变浏览器/字体……获得通过」。跨版本的文字度量与栅格化差异会落在
几个像素量级，正好是 2px 门禁的量级。

所以下面的数据是**开发期观察**，不是门禁结果。但其中量级远超版本差异的项（例如
91px）不受此限，可以直接采信。

## 观察结果：1440 light 首页，97 个选择器

| 分类 | 数量 |
|---|---|
| 在 2px 容差内 | 21 |
| 具名例外（品牌文字／版块名导致的文字盒宽度） | 2 |
| 参考侧存在、实现侧无此元素 | 6 |
| 超出 2px 且不属例外 | 11 |

### 一、内容量差异，不是几何缺陷

`body`、`main.wrap`、`div.forum-layout`、`div.forum-main`、`ul.post-list` 的高度
各差 1416–1523px；`div.tab-bar` 宽度差 200px、`a.tab` 位置差 78px。原因是夹具只有
12 条合成主题、标签页数量也少于参考站首页。这是内容量而非布局几何，按 `05` §11
用户生成内容可遮罩的口径不计入。

### 二、导航条目数差异，已由项目所有者裁定为基准差异

`nav.forum-nav` 宽度 563.94 → 270.88（Δ −293.06），`a.forum-link` 54.59 → 46.00
（Δ −8.59），`a.forum-more-toggle.nav-sister` 位置随之左移 293px。按 `DEC-068` 与
`05` §10 现行条文，导航条目数属基准差异而非待修偏差。

### 三、实质偏差：搜索框在桌面档宽 91px

| 视口 | 参考 | 我方 | 差 |
|---:|---:|---:|---:|
| 1440 | 158.95 | 250.00 | **+91.05** |
| 768 | 250.00 | 250.00 | **0** |
| 760 | 491.63 | 495.63 | +4.00 |
| 390 | 132.90 | 136.35 | +3.45 |

差异的性质不是"数值抄错"，而是**尺寸机制不同**：参考站的搜索框随视口伸缩
（1440 被更宽的导航挤到 159，768 导航隐藏后回到 250，760 拉到 491.63），而
`apps/web/static/css/site.css:228` 在桌面档写死 `width: 250px`，只有窄档
（`site.css:348`）才 `flex: 1`。768 处两者恰好都是 250，所以完全吻合。

**这一项不能就此判为待修**：参考站 1440 的 159 是被它自己那套更宽的导航挤出来的
结果。我方导航按 `DEC-068` 只有六项，若改成同样的弹性机制，算出来只会比 159 更宽，
不会更接近。要判定我方取值是否正确，需要参考站在六项导航下的表现，而那不可得。

760 与 390 的 +4.00／+3.45 出现在两边都走弹性机制的档位，与导航无关，是页头 flex
行内的间距或内边距差异，超出 2px 门禁，属可修范围。

搜索入口按 `DEC-037` 属**不可遮罩**区域，这两项都不能用遮罩规避。

### 四、参考侧存在、实现侧没有的六个元素

| 选择器 | 参考尺寸 |
|---|---|
| `div.top` | 1425 × 57 |
| `button.forum-more-toggle` | 74 × 34.5 |
| `form.script-toggle` | 43 × 30 |
| `button.theme-toggle` | 30 × 30 |
| `div.main-panel` | 888 × 2487.5 |
| `div.topic-toolbar` | 888 × 49.5 |

其中 `form.script-toggle` 与 `button.theme-toggle` 是参考站的 JS 驱动控件；本站
A00 副本改为纯 SSR 链接，这正是 `90` §5「无 JavaScript 可用」得以通过的原因
（页面 `<script>` 数为 0）。`button.forum-more-toggle` 在本站是
`a.forum-more-toggle.nav-sister`（button → a）。其余三个是包裹层 div。

这些属**结构差异**而非几何偏差，且 `AGENTS.md` 记明 A00 的「模板结构与 CSS 类名
自此冻结」，本轮不改动。是否需要补齐，属 `05` 的裁决范围，此处只登记。

## 结论

A 级门禁两半均**未通过也未失败**——像素这半无基准可比，几何这半的浏览器版本不满足
`05` §3。开发期观察查出一项确定可修的偏差（760／390 搜索框 +4.00／+3.45px）、一项
需要参考站在六项导航下的数据才能判定的偏差（1440 的 +91.05px），以及六个结构差异。

不据此宣称 `WP-MVP-E04` 或 `05` §15 任何条目通过。
