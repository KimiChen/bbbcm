| 用例 | 覆盖的 90 §5 安全条目 |
|---|---|
| 管理响应安全头全覆盖 | 点击劫持、CSP、缓存、安全响应头 |
| 未登录不泄露管理内容 | 垂直越权、C3 永不返回 |
| 响应不泄露 Secret/连接串/主机路径 | 日志、错误、HTML、JSON 敏感泄露 |

| 改状态动作不可经 GET 到达 | CSRF |
| 资产响应禁止 MIME 嗅探 | XSS（sniffing 导致的脚本执行） |

## 本轮修复的缺陷

首个用例即抓到：`secure_headers` 原先只在 `render` 的成功分支与 `redirect` 里调用，
而 handler 里有**六处** `StatusCode::X.into_response()` 提前返回——`/manage` 的 404 与 500
不带任何安全头。后台 URL 本身带案件与主题 ID（`99` §1008），缺 `Referrer-Policy` 等于
把它送到站外，缺 `no-store` 则允许中间层缓存管理响应。

修复方式是把安全头改由 `axum::middleware::map_response` 统一施加，而不是在每个 return
前逐个调用——将来新增的任何提前返回都不会再漏。这是无歧义的实现遗漏，`99` §1008 已
写明「管理响应带…」，不存在事实源冲突，故直接修复未另行请示。
