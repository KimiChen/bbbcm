# WP-MVP-E01 治理路径 E2E：本轮可达范围与一处观察（2026-09-07）

## 已验证

`bbbcm-cli user promote`（`AUTH-014` 首账号提权）实现完整，执行后：

- 建立 staff principal（`bcm_identity_staff_principals` 一行，`status = active`）；
- 标准错误打印 `[ALERT] AUTH-014 首账号提权 已执行`，供运维采集；
- 提示「首次管理登录将强制绑定 TOTP，未完成前只能访问绑定流程」。

开启 `manage_console` Flag 后的路由行为：

| 路径 | 未认证状态 |
|---|---|
| `/manage/login` | 200 |
| `/manage`、`/manage/mfa`、`/manage/cases`、`/manage/reports`、`/manage/content` | 303（转登录） |

未认证一律不进入，且不泄露后台结构，与 `03` §1 一致。

## 登录路径：两处缺陷已修复

以提权后的账号提交管理登录，持续返回 **401**。同一账号的**普通登录在同一次会话中
是成功的**（并完成了发帖与编辑），因此凭据本身正确。根因已定位，见下节。

## 缺陷（已定位）：`/manage/login` 永远不可能成功

排查上述 401 已定位到根因，属**阻断级**：管理控制台无人能登录。

### 证据链

| 观察 | 结论 |
|---|---|
| `trust.risk_events` 无 `manage.login` 事件 | 失败发生在 `record_risk` 之前 |
| `platform.idempotency_records` 无 `identity.manage.login` scope | 失败发生在 `execute_command` **之前** |
| `management_login` 在 `execute_command` 前只调 `prepare_challenge` 与 `public_command` | 缩小到这两处 |
| `prepare_challenge` 在无挑战要求时提前 `Ok(None)` | 排除 |
| `public_command` → `repo::principal` | **定位于此** |

### 根因

`repo::principal`（`crates/identity/src/repo.rs:106`）按 `token_hash = sha256(preauth)`
查 `identity.request_principals`，**要求该行必须已存在**（`.ok_or(InvalidInput)`）。

普通登录的上下文来自 `GET /login` 时 `create_preauth` 签发的真实 preauth
（`crates/identity/src/http.rs:460`），token 与 csrf 被渲染进表单、POST 时带回，
因此 principal 行存在。

而控制台在 `apps/web/src/manage_web.rs:160` 用**三个随机 `new_operation_id()`**
现造 `RequestContext`：

```rust
// 复用与普通登录完全相同的请求上下文构造：四维限流、风险信号与挑战
// 都在这一层生效，管理登录不走任何简化路径。
let context = identity::contract::RequestContext::new(
    identity::contract::Secret::from(platform::transaction::new_operation_id()),
    identity::contract::Secret::from(platform::transaction::new_operation_id()),
    platform::transaction::new_operation_id(),
);
```

该注释与实际行为相反：它并未复用普通登录的上下文构造，而是凭空造了一个。
随机 token 在 `request_principals` 里没有对应行，`repo::principal` 必然返回
`InvalidInput`，`public_command` 失败，`management_login` 报错，控制台统一收敛为 401。

**旁证**：`/manage/login` 表单里 `csrf` 的 `value` 是空字符串——因为控制台没有
preauth 可渲染。普通登录表单里该值非空。

### 影响

**完整模式与体验模式下管理控制台都无法登录**，`AUTH-014` 的首账号引导因此走不通，
`/manage` 全部治理功能不可达。`bbbcm-cli user promote` 本身正常，问题在登录一步。

### 已修复

`ConsoleBackend` 新增 `preauth()`；`GET /manage/login` 签发一对 preauth，csrf 渲染进
表单、token 写入仅限 `/manage` 的 HttpOnly cookie；POST 时两者一并带回，装配层据此
构造 `RequestContext` 而不再现造随机值。登录失败分支**重新签发**一对——preauth 是
一次性的，沿用旧的会让用户第二次提交必然再失败，看起来像密码一直错。

### 修复过程中暴露的第二个缺陷：未认证端点可达的 panic

preauth 修好后，流程首次真正走到命令执行，随即 **panic**：

```
thread 'tokio-rt-worker' panicked at crates/identity/src/core.rs:129
```

`management_login` 把 `"ready"`／`"binding"` 两个词当作 `resource_id` 传给
`SafePayload::with_reference`，而 `platform::outbox::is_reference` 只接受**正整数或
UUIDv7**。`with_reference` 返回 `Err`，紧随其后的 `.expect("core uses opaque references")`
把它变成 panic。

**严重性高于原来的 401**：`/manage/login` 是未认证可达端点，一次 panic 就是一个
拒绝服务面。它此前被第一个缺陷掩盖——流程根本走不到这一步。全仓仅此一处把非
数字串当作 `resource_id`（另一处 `response(Some(&reference))` 传的是真实 id）。

已改为用受信整数编码访问级别（1 = 已绑定、2 = 需绑定），解码侧对未知取值一律按
未认证处理，不猜默认值——猜「已绑定」会让未完成 MFA 的会话直接进入后台。

### 修复后实测

| 路径 | 登录前 | 登录后（未完成 TOTP 绑定） |
|---|---|---|
| `POST /manage/login` | 401 | **303**（无 panic） |
| `/manage/mfa` | 303 | **200**（强制进入绑定流程） |
| `/manage`、`/manage/cases`、`/manage/reports`、`/manage/content` | 303 | **303** |

与 `AUTH-014` 提权时打印的「未完成前只能访问绑定流程」以及 `03` §1 完全一致：
会话已建立，但未绑定 MFA 前只有绑定流程可达。

## 附带问题：失败不留服务端痕迹

排查过程本身暴露了第二个问题。两次失败的管理登录：

| 位置 | 是否留痕 |
|---|---|
| 应用日志（159 行全量） | **无任何 manage 相关记录** |
| `trust.risk_events` | **无 `manage.login` 事件**——同一会话的 `registration`／`login`／`topic`／`edit` 四条都在 |
| `audit.audit_events` | 仅有提权那一条 |

控制台把「账号不存在／非 staff／密码错误」收敛为同一错误再渲染 401，这条设计本身
正确（不给枚举线索）。问题在于**服务端也没有记录**：反枚举要求的是不告诉客户端，
不等于不记录在服务端。

两点后果：运维在首账号引导失败时无法区分「密码错」与「装配缺陷」——上面那条阻断
缺陷正因此被掩盖成一个无解释的 401；以及针对 `/manage/login` 的凭证填充不留任何
可检测信号，而这正是 `90` §5 安全矩阵「凭证填充」要防的场景之一。

## 未覆盖（2026-09-07 同日在真实 PostgreSQL 上查证后更正）

原文写的是「登录后的案件队列、举报处置、内容管理等治理动作，均依赖上述登录成功」。
这句话不准确：登录修好之后它们仍然不可达，原因与登录无关。

真实 PostgreSQL 上完成登录与 TOTP 绑定后，队列页返回 200 但正文是「没有查看案件
的权限」。查证结论是四个已登记交付缺口叠加：`site_owner` 恰好四项极高危权限、
不含任何 `moderation.*`（`03` §4 职责分离，拒绝是对的）；`user promote` 不分配
角色；受控命令 `assign_role` 除测试外无任何调用方；举报入口 `moderation::http::router()`
返回空 Router。

即：治理动作当前无法通过任何已实现路径端到端执行，属 `D01`／`D04` 剩余交付。
完整实测见 [`governance-path-postgres.txt`](../../wp-mvp-e01/dev-20260907/governance-path-postgres.txt)。
