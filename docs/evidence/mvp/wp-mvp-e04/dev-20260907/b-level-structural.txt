# WP-MVP-E01／E04 浏览器结构化检查（B 级，2026-09-07）

`05` 第 6 节把页面分两级：**A 级**适用第 10 节的像素与几何阈值，**B 级只做结构级
检查**，检查项为「无横向溢出、触控目标不小于 44px、对比度达标、键盘可达、
无 JavaScript 可用、错误态可达」。

本次执行的是**结构级检查**，它不依赖字体渲染基准，因此不需要 `05` 规定的固定
浏览器/字体/缩放环境。**A 级的像素与几何比对仍未执行**，本文件不构成视觉基准，
也不得据此宣称 `WP-MVP-E04` 完成。

## 方法

- 夹具：`/__fixtures/a00/{page}` 全部 14 页（`05` 冻结的稳定夹具）。
- 视口：`90` §5 规定的 1440 / 1024 / 768 / 760 / 390 / 320px。
- 主题：light 全量；dark 抽查 1440 与 390。
- 测量：在与目标视口等宽的 iframe 中真实布局后读取几何值，媒体查询按 iframe
  视口宽度生效。共 154 个「页面 × 视口 × 主题」组合。
- 无 JavaScript 项用 `curl` 取原始 HTML，完全不执行脚本。

## 触控热区：实测否决，未采用

原计划用绝对定位的 `::after` 把热区撑到 44px、不动可见尺寸。实测把它否决了：

| 观察 | 数值 |
|---|---|
| 390px 下 8 类受控元素的实例数 | 68 |
| 其中扩大后**与相邻目标重叠**的 | **54** |
| 390px 下全部非内联交互目标 | 559 |
| 低于 44px（`05` §6 门槛）的 | **505** |
| 低于 24px（WCAG 2.2 AA 的 2.5.8 门槛）的 | **192** |
| 低于 44px 但满足 2.5.8 间距替代条款的 | 349 |

两点结论：

1. **重叠使方案失效**。热区重叠让点击归属不确定，这比目标偏小更糟——是把一个
   问题换成另一个。给 505 个目标逐个加热区，等于给整个列表铺满互相重叠的判定区。
2. **规模远超预估**。用户批准该方案时的前提是「仅对不达标的几个控件」，实测显示
   低于 44px 的是 505/559，即几乎整个设计。前提不成立。

另需注意门槛差异：`05` §6 写的 **44px** 相当于 WCAG 2.5.5（AAA）与移动 HIG 的量级；
而 `90` §5 要求的 **WCAG 2.2 AA** 对应的是 2.5.8「目标尺寸（最小）」的 **24×24**，
且允许用间距替代。按 AA 口径，硬性不达标的是 192 个而非 505 个。

因此触控目标一项**回到用户裁决**，本层未做任何热区改动。
