# WP-MVP-E01 HTTP/E2E：真实业务路由状态矩阵（2026-09-07）

此前的 E2E 记录只能驱动 A00 夹具，因为内容/身份服务未装配。本次补齐装配后，
**业务路由本身**可达，`90` §5「成功、空、错误、未认证、未授权、冲突、过期和
依赖失败」八类状态中的**七类**已在真实路由上验证。

## 装配

装配缺的是三项 Secret 与两项本机配置，全部为一次性合成值，只经进程环境或
已被 `.gitignore` 忽略的 `config/local.toml` 注入，不写入仓库：

- `BBBCM_CONTENT_CURSOR_KEY`、`BBBCM_IDENTITY_TOKEN_KEYS`、`BBBCM_IDENTITY_RISK_KEY`
- `identity.active_token_version`、`adapters.mode = "local_test"`（邮件只落库不外发）

Feature Flag 由**运维方式**直接改库开启（`public_read`、`registration`、
`email_verification`、`topic_creation`、`reply_creation`、`search`、`rss`）——
`bbbcm-cli flag set` 随 `WP-MVP-A02` 才接入，当前没有受控写入口。

同样以运维方式插入了三份**合成政策文档**（`terms`／`privacy`／`community`，状态
`synthetic`）——`CurrentPolicyReader` 在 development/test 下接受该状态，但种子不产生
它们，缺失时注册整体不可用（即上表记录的 503）。这两处「直接改库」都不是正常运维
路径，写在这里以免被误读为产品已具备相应入口。

## 状态矩阵

| 类别 | 路径 | 状态 |
|---|---|---|
| **成功** | `/`、`/new`、`/hot`、`/pinned`、`/featured` | 200 |
| **成功** | `/login`、`/robots.txt`、`/sitemap.xml`、`/feed.xml` | 200 |
| **成功** | `/search?q=abc` | 200 |
| **空态** | `/search?q=`、`/search?q=zzzzzzzz` | 200，页面呈现「没有匹配的标题。」与「体验模式：仅支持标题搜索。」——**是空态而不是错误** |
| **不存在** | `/t/999999`、`/forums/nope`、`/tags/nope` | 404 |
| **未认证** | `/settings/profile` | 401 |
| **未授权** | `/me/topics` | 403 |
| **未认证跳转** | `/manage`、`/manage/cases` | 303（转登录，不泄露后台结构） |
| **依赖失败** | `/register` | 503（挑战 provider 未装配，失败关闭而非放行） |

### 过期／无效令牌（补测）

带 CSRF 向 `/reset-password` POST 一个无效令牌：

| 项 | 结果 |
|---|---|
| 状态 | 400 |
| 页面提示 | 「请求未能完成，请检查输入后重试」 |

提示刻意通用，**不透露令牌是否存在或是否已过期**——区分这两者就给了攻击者一个
枚举有效令牌的信号。这条是安全属性而不是可用性缺陷。

### 冲突：域层已验，HTTP 层未验

**冲突**是八类里唯一未在 HTTP 层构造的。它在**领域与数据库层已经验过**：
`platform-db` 的 `version_conflict_prevents_lost_update`（陈旧版本必须冲突、
不得静默覆盖、冲突分支无部分生效）与 `content` 的并发楼层用例（版本冲突下重读重试
后楼层仍不重不漏）。

未在 HTTP 层构造的原因如实记录：注册是**邀请制**，而种子不产生邀请码；种子建的四个
版块状态均为 `draft`，发帖前需先激活。要走到「登录后编辑并撞版本冲突」需要连续五步
直接改库（造邀请、注册、验证邮箱、激活版块、发帖），那样得到的是一个人工拼装的环境，
而不是真实流程——本轮选择不这么做，如实标为未覆盖。

## CSRF

无令牌 POST：

| 路径 | 状态 |
|---|---|
| `/login` | 400 |
| `/register` | 400 |
| `/topics/new` | 403 |

三条都被拒绝，没有一条以「表单缺字段」的方式走进业务逻辑。

## 公开页安全响应头

```
cache-control: private, no-store
referrer-policy: no-referrer
x-content-type-options: nosniff
content-security-policy: default-src 'self'; script-src 'none'; frame-ancestors 'none'; base-uri 'none'; form-action 'self'; object-src 'none'
```

`script-src 'none'` 值得单独指出：它与此前实测的「页面 `<script>` 数为 0」互相印证
——不是「暂时没写脚本」，而是策略层面直接禁止执行脚本。配合 `object-src 'none'`
与 `base-uri 'none'`，XSS 的主要执行面被 CSP 关掉了。
