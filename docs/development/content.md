# 公共阅读与内容事务的本机开发

本页是操作说明；需求、状态和决策以 `plan/README.md`、`plan/99-traceability.md` §5.9 与 DEC-052/053 为准。所有测试使用临时 SQLite、普通合成账号和明确标注的合成政策，不提供授级、Flag 写入或管理入口。

## 运行与装配

沿用 `docs/development/database.md` 和身份本机说明的配置及迁移命令。迁移新增 PG/SQLite 的 `0009_content.sql`、`0010_content_access.sql`，不改已应用 0001–0008；MySQL 继续占位。迁移不会启用任何业务 Flag、授予 T0/T1 或植入可公开发布的内容。

内容游标使用通过 Secrets 层注入的 `BBBCM_CONTENT_CURSOR_KEY`，格式为 32 随机字节的小写十六进制，与身份邮件和风险密钥分开。配置文件不得保存该值。缺少此 key 时内容服务不装配；缺失或未批准的内容政策、作者默认隐私和风险策略不会使用猜测值。已有 `BBBCM_IDENTITY_RISK_KEY` 在内容风险用途下采用独立 HMAC 域，不接收客户端声称的等级、挑战结果或风险决定。

正常运行时所有业务 Flag 仍关闭。只有测试函数在其独占临时库内设置 `public_read`、`topic_creation`、`reply_creation` 等受控状态。配置 schema 没有内容政策默认参数，没有 `flag set`、信任授予、管理员登录或其他运行时绕过。DEC-053 未答复时，本轮具备真实数据库及受信接口实现，但正常发布/本人维护、未知作者隐私对应的正文和资料内容投影仍不可用；公共空列表可以正常读取，不填充演示帖子或虚构计数。

## 定向验证

```bash
cargo test --locked -p content
cargo test --locked -p identity content_access_tests
cargo test --locked -p bbbcm-web content_runtime_tests
cargo test --locked -p bbbcm-web content_risk::tests
./scripts/dev-check.sh
python3 scripts/asset_freeze.py
```

`apps/web/src/content_runtime_tests.rs` 复用既有身份 fixture：先真实注册、消费本地验证令牌，再登录；验证后仍是 pending，写入被拒绝。只有显式测试 seed 修改合成信任快照，随后经过正常内容 core 和应用 authority 完成发帖、回复、修订、收紧可见性、幂等重放、Outbox 和分析排除验证。无 JavaScript 的 SSR 测试用真实 cookie/CSRF 和表单 POST，再读取数据库结果及页面。合成的长度、时间窗、T1 额度、日界线、作者公开默认、首帖整主题删除和风险参数不是正式产品值。

风险开发测试使用内存 TokenBucketLimiter 和故障适配器，分别覆盖 Redis 关闭的 `NoProtection`、开启时四维预算、开启但不可用、缺可信 peer、重复设备 cookie、伪造转发头及 opaque context 的账号/动作绑定。令牌桶不承担严格每日配额。挑战、重复文本处置和正式阈值仍等待 DEC-053；没有模拟真人挑战成功来开放内容。

## 读取、维护与恢复合同

- 首页四视图和版块/标签采用签名 keyset 游标；签名绑定筛选条件、访问主体和已提交水位。排序使用该水位时的不可变主题历史，新回复对旧主题的移动不会使同次遍历漏项。新增主题/回复留给下一次第一页遍历。
- 回复每页 50 条，按永久楼层递增；删除不重排。`/posts/{id}` 生成带签名分页位置的主题链接和 `#post-{floor}` 锚点。它只承诺永久楼层定位，不是 DEC-017 移帖跳转。
- 每一页执行当前可见性检查；权限收紧、隐藏和删除可将内容立即移出原遍历，安全移除不属于分页漏项。成员内容和私密响应不使用公开缓存。
- Markdown 原始 HTML 显示为文字，URL 与生成的 HTML 使用严格白名单。图片仅保留替代文字，不加载远程资源。站内引用不复制目标正文；目标后来不可见时移除目标链接并保留来源自身正文。预览与最终渲染使用相同规则。
- 本人编辑和删除执行当前会话、CSRF、邮箱验证、账号/限制、信任及窗口检查，版本不匹配返回冲突。每次成功维护追加内部修订；不提供修订改写或公开历史入口。
- 内容、修订、楼层、严格发布消费事实、必要计数、权威搜索文档、幂等响应和 Outbox 在同一事务提交。SQLite 搜索文档正文为空，保留标题/权限/状态/游标；完整搜索后续。可见性收紧同步重写主题下的权威搜索文档。
- 公开正文缓存先从主库核对当前权限及版本，再取版本 key；站内链接、引用、成员和待审内容绕过。TTL 30 秒，失效经既有 Outbox/Worker；缓存故障回源，主库授权故障不回退敏感旧页面。
- 提交结果未知时保存原幂等键、原载荷与操作 ID，用表单查询入口 `/content/operations` 复核；`not observed` 不等于回滚。不能换新幂等键盲目重发。回执查询也验证当前本人会话与权限，只返回最小回执，不返回正文、密钥或原请求。

临时 fixture 在结束时清理自身目录；失败残留仅在系统临时目录按 `bbbcm-*` 合成前缀人工核对后处理。本机长期 SQLite 如需恢复，先停止使用该库的 Web/Worker，再按数据库说明备份或恢复。不得清空非本地数据库，不执行 Redis `FLUSHDB`，不改写已应用迁移。Worker 重启从主库 Outbox 与持久投影回执恢复；重启不需要重建业务内容，也不重复累计排除账号的分析数据。

## 本轮保留缺口

最近浏览、搜索页面/引擎、Feed/sitemap/SEO、跨设备阅读位置、有效/首次行为统计、互动/引用通知、上传/附件/头像处理、完整草稿、管理状态操作、作者隐私设置、授级流程和正式风险挑战不在本轮交付完成范围。风险前置拒绝尚不全量形成内容风险事件；账号/合成测试排除已接，其他未建立权威来源的角色/机器人/活动排除不能声称完成。真实 PG/Redis、安全、并发、性能和正式视觉矩阵按 DEC-020 留统一硬化。
