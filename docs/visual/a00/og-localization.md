# A00 OG 与邮件页头品牌组合

`og-image.svg` 以本轮当前公开 OG 图为视觉依据，使用 SVG 代码重建 1200×630 黑色背景、60px 网格、中心金色光晕、白色章形和两层文字。原始 WebP 没有被修改、覆盖或作为新图的位图底层。原图哈希、只读像素测量、重建参数、字体计算值、生成器哈希与产物哈希见 [`og-localization.json`](og-localization.json)。参考图只在 Git 忽略目录留存；复跑生成器不需要它。

全部可见文字替换为“草莓论坛”，章形直接内联本轮 `brand-symbol.svg` 的边框和两行本地化文字，固定为白色以配合深色背景。网格、光晕和字体参数来自这张公开位图的观察与测量，不冒称已经取得参考站原始设计文件或精确 CSS。品牌文字变化会改变字形和文字度量；这些开发期构造记录不是 `WP-MVP-E04` 的像素、几何或 WCAG 门禁。

`email-header.svg` 是本项目为邮件页头交付的 640×160 共享品牌组合，使用同一本地化章形和“草莓论坛”。未观察到参考站私有邮件，也不声称复制了参考站邮件版式；这个资产本身不实现邮件模板、发信或业务接口。

复跑命令为 `node scripts/a00-og-render.mjs`。脚本只读取本地品牌 SVG，要求其固定哈希，重建两个 SVG 后连接现有本机 Chrome 9222，创建新的匿名上下文，从仅监听 loopback 的临时静态服务渲染 OG PNG；不访问参考站资源、不读取 Cookie 或会话、不执行页面脚本。两次连续截图必须字节相同，输出尺寸必须为 1200×630。邮件预览只写到忽略目录；对外资产仍是 SVG。

同一命令按当前旧称词表检查 SVG 文件名与文本、外部资源引用和 PNG 文本块，并调用已有的 macOS Vision OCR 工具检查 OG PNG，缺少 Swift 或 OCR 工具时明确失败。开发期人工查看 OG 与邮件预览后确认章形和文字均为本项目品牌；OCR 只是辅助，不代替人工复核。逐次扫描结果和对应 PNG 哈希写入同一 JSON。

字体使用本机 `PingFang SC` 和系统 fallback，没有分发系统字体文件。跨系统渲染可能改变文字度量，因此记录实际浏览器、字体计算值与本机输出哈希，不将两次本机截图一致性扩大为跨环境像素保证。

三项资产的许可仍为 `unconfirmed`、可再分发性 `pending`、公开发布 `not-approved`，按 `DEC-045` 允许本机版本化。源自参考品牌的图形不被改标为本项目 AGPL，也不把项目批准记录冒充权利方授权。逐项清单见 [`licenses/localized-og-assets.json`](licenses/localized-og-assets.json)；部署、推送及对外发布不在本轮范围。
