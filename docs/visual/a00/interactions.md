# A00 移动交互开发诊断

本记录只说明本轮本地合成夹具的实际交互诊断结果，不是 WCAG 验收、六视口像素比较、`WP-MVP-E04` 门禁或正式视觉基准。工作包状态与剩余交付统一见 `plan/99-traceability.md` 第 5.1 节。

## 测试对象与环境

- 日期：2026-09-05，Asia/Shanghai。
- 浏览器：现有本机 9222 调试端口的 Chrome/152.0.7977.76。
- 视口：390 × 1000 CSS px；deviceScaleFactor 为 1，未施加页面缩放。
- 页面 JavaScript：通过 CDP `Emulation.setScriptExecutionDisabled` 禁用。
- 页面：本机测试进程的 `/__fixtures/a00/home?theme=light`，夹具版本 `a00-synthetic-v1`；随后通过本地 GET 链接切换 `dark` 与 `system`。
- 使用新建的隔离浏览器上下文；不读取 Cookie、会话或认证状态。测试完成后销毁上下文并关闭独立测试进程。
- 本轮测试针对原生 `details` 移动抽屉和主题菜单接入后的构建。结果是该构建的开发期证据，不代替最终版本的完整交互回归。
- 页面状态、矩形与计算值由 CDP 读取；点击和按键通过 `Input.dispatchMouseEvent`、`Input.dispatchKeyEvent` 发给浏览器，未用脚本直接切换 `open` 或主题属性。

| 操作 | 步骤与结果 |
|---|---|
| 打开菜单 | 点击移动菜单摘要按钮，`details.mobile-menu.open` 变为 `true`。 |
| 抽屉与遮罩 | 抽屉矩形为 `(0, 0, 300, 1000)`；遮罩矩形为 `(0, 0, 390, 1000)`；遮罩计算色为 `rgba(5, 0, 56, 0.42)`；根元素 `overflow` 为 `hidden`。 |
| 关闭控件 | 关闭控件矩形为 `(256, 14, 28, 28)`。点击该控件，菜单关闭。28px 来自本轮参考计算值，未据此宣称触控目标符合 WCAG。 |
| 点击遮罩关闭 | 再次打开菜单，在视口 `(380, 500)` 点击遮罩，菜单关闭。 |
| Enter 开关 | 聚焦菜单摘要按钮，发送完整 Enter 按键事件，菜单打开；再次发送，菜单关闭。 |
| 深色主题 | 打开主题菜单并点击“深色”，浏览器导航到同一夹具的 `theme=dark` GET URL；页面 `data-theme` 为 `dark`，body 背景为 `rgb(13, 14, 20)`。 |

## 已复现的键盘焦点缺口

抽屉打开时，当前实现锁定背景滚动并显示遮罩，但没有隔离背景焦点。已按以下步骤复现：

1. 在 390 × 1000 视口、页面 JavaScript 禁用的条件下，聚焦移动菜单摘要按钮并用 Enter 打开菜单。
2. 连续按 Tab。第 1 至第 8 次依次聚焦“全部主题”“问答/实战”“AI”“域名与主机”“站务”“登录”“注册”“发布主题”，均处于抽屉内部。
3. 第 9 次 Tab 聚焦抽屉后方的 `.brand`；第 10 次 Tab 聚焦 `.search-input`。两次检测时菜单仍为 `open`，焦点元素中心点被 `.mobile-menu-head` 覆盖。

涉及实现位置为 `apps/web/templates/partials/header.html` 的 `details.mobile-menu`、`apps/web/static/css/site.css` 的抽屉遮罩和滚动锁定规则。Enter 能打开和关闭菜单，不能据此宣称完整键盘路径通过。

完整 Tab 焦点管理、背景焦点隔离、Escape 关闭及关闭后的焦点恢复增强留给 `WP-MVP-E04`。本轮没有验证 Escape 关闭；当前没有为原生 `details` 添加自定义 Escape 增强。此缺口必须保留在后续验收清单中。

## 按键测试重测说明

第一次 Enter 自动操作只发送了 key/code/virtual-key 信息，没有发送回车字符，浏览器没有激活原生摘要控件，因此自动断言显示“keyboard open failed”。随后确认焦点确实位于 `.mobile-menu-button`，并在 keyDown 中补充 `text` 与 `unmodifiedText` 为回车字符（CR）；keyUp 保持普通 Enter 释放事件。

使用完整事件后，独立重测和整套操作重测均确认 Enter 能打开、再次按 Enter 能关闭。这是 CDP 按键构造的修正，不是一次页面键盘缺陷修复；上节的第 9 次 Tab 背景焦点问题则是真实页面缺口，两者不能混为一谈。

## 验证边界

本轮检查未覆盖完整屏幕阅读器体验、焦点循环与恢复、Escape、移动软键盘、触屏手势、跨浏览器行为或六视口双主题矩阵。也未把参考站禁用脚本后的公开结构观察当作参考站完整交互行为的验证。完整验证与批准仍按 `plan/05-visual-brand-spec.md`、`WP-MVP-E04` 和 `DEC-019` 执行，不授予 `Verified`。
