# 05 视觉与品牌复制规范

## 1. 不可放宽的规则

- 公开视觉严格复制 `https://sb.sb/` 可公开观察的视觉语言和品牌标识，不接受“相似即可”。
- 项目名称为“草莓社区”，页头品牌文字为“草莓论坛”。
- 所有运行资源保存在本地，不热链参考站 CSS、字体、脚本、图片或 API。
- `/manage` 使用相同品牌资产、token 和组件外观，但后台信息架构以本项目需求为准。
- 本轮 A00 重做的视觉与响应式规则若与当前公开参考实测冲突，以实测值为准并登记（`DEC-043`，用户 2026-09-05 批准）；不凭旧规范数值改写参考外观。后续无障碍改动仍须按组件登记原因和批准人，不能借此整体重设计。

## 2. 基准版本

第一份可发布基准记为 `visual-baseline-v1`。由于参考站文字与目标品牌文案不同，基准由两部分组成：

1. 参考站公开截图，用于冻结颜色、字体、密度、几何、边框、阴影、布局和响应式行为。
2. 使用目标品牌文字和本项目稳定夹具生成的批准实现基准，用于逐像素发布回归。

该组合方式已由 `DEC-057`（2026-09-06）批准并启用，`DEC-019` 关闭。`visual-baseline-v1` 以 `WP-MVP-A00` 已交付的 14 个隔离 SSR 夹具、30 项本地源资产与「草莓论坛」品牌文案冻结为实现基准；参考站公开截图继续承担几何比对角色。冻结不等于门禁通过：第 15 节全部条目仍在统一硬化阶段（`WP-MVP-E04`）用第 3 节规定的固定环境重拍验证（`DEC-020`）。后续真实页面只能在本基准上演进，不得另起一套基准；变更基准须按 `06` 第 5 节重新批准并递增版本号。

基准采集与本地化实现先行，由 `WP-MVP-A00` 作为开发第一步完成（`DEC-021`，见第 13 节）；像素级验收推迟到功能开发完成后的统一硬化阶段集中执行（`DEC-020`）。基准已冻结不等于门禁通过：硬化阶段验收完成前，不得宣称视觉门禁通过。

## 3. 基准采集环境

本节的完整环境记录用于正式基准截图，在统一硬化阶段执行（`DEC-020`）；开发期 `WP-MVP-A00` 的本地化采集按第 13 节执行。

每次基准记录：

- URL、UTC 日期和采集者。
- Chromium 精确版本。
- 操作系统、设备缩放和截图倍率。
- 字体文件、fallback 和渲染设置。
- 视口、主题、语言和固定夹具版本。
- 截图尺寸、SHA-256、遮罩区域和遮罩原因。
- 页面滚动位置、动画关闭和数据稳定策略。

固定视口：`1440`、`1024`、`768`、`760`、`390`、`320px`。每个视口覆盖 light/dark；系统主题另做行为验证。

## 4. 资产清单

必须本地版本化：

- Logo/brand mark。
- favicon。
- 应用图标。
- Open Graph 品牌图。
- 邮件品牌图。
- UI 图标集。
- Web 字体文件。

资产清单记录逻辑名、内容哈希文件名、MIME、宽高、主题适用性、可访问名称和 SHA-256。带文字的资产只使用“草莓论坛”或批准的“草莓”。

资产分两类（`DEC-035`）：

- **构建期资产**：随仓库版本化，由 `WP-MVP-A01` 的构建脚本生成内容哈希与 `manifest.json`，适用第 10 节的像素与几何门禁。
- **运行时资产**：`ADMIN-005` 允许在 `/manage/config` 运行时替换的 Logo、favicon 与应用图标。它们经后台上传后落对象存储、按内容哈希命名，由运行时覆盖层补充进 manifest；每次替换写入审计并记录内容哈希与生效版本。基准无法预知未来上传的图形，因此对这类资产**只校验尺寸、宽高比、格式与占位盒模型**，不做逐像素比对；`visual-baseline-v1` 冻结的是布局与占位约束，不是图形本身。

每项资产还必须登记以下三列，用于界定与项目许可证（AGPL-3.0-only，见根目录 `LICENSE`；原 DEC-023 行已由用户删除）不同的第三方权利：

| 列 | 含义 |
|---|---|
| 来源 | 本项目自制 / 采集自参考站 / 第三方项目（注明名称与版本） |
| 许可证 | 该资产自身的许可证（自制资产随项目 AGPL-3.0-only；字体按其自身许可，如 OFL-1.1） |
| 证据 | 许可证原文或来源页面的本地留存路径 |

资产清单是 `DEC-021` 的本地化交付项；按 `DEC-046`，资产可以先在本机提交，清单随后补齐，逐项登记完成不是本机提交的前置条件。本轮仅本机开发和提交；按用户最新替换的任务目标及 `DEC-045`，未知许可如实记录，不作为本轮完成或本机提交的阻塞，不部署、不推送。

对 SVG 文本、文件名、元数据和栅格图执行旧称扫描；栅格图使用 OCR 加人工复核。「旧称」指参考站名称与域名（`sb.sb` 及其变体）以及本项目的历史或内部代号；扫描词表随 `WP-MVP-A00` 产出，落在 `docs/visual/a00/` 下版本化，上述四类扫描均以该词表为准。

## 5. 设计 token

冻结并在浏览器读取计算值：

- 背景、表面、边框、主文字、次文字、弱文字。
- 品牌色、链接、成功、警告、错误和焦点。
- 字体族、字号、行高和字重。
- 间距、容器宽度、列宽和栅格间隔。
- 边框宽度、圆角、阴影和分隔线。
- 交互高度、图标尺寸、头像和状态标记。
- 响应式断点和显隐规则。

字号与 letter-spacing 按当前公开参考的组件及断点计算值冻结（`DEC-043`），不再统一强制字距为 0，也不禁止参考站已有的离散断点字号变化。已观察页头品牌为 16px / `letter-spacing: -0.01em`，主题标题桌面为 15px、移动为 14.5px；禁止未经观察引入流体字号缩放。固定格式控件使用参考站的稳定尺寸和响应约束，动态文字不得引发布局跳动或重叠。

## 6. 页面范围

页面分两级（`DEC-038`，2026-09-05 批准）。分级是 `visual-baseline-v1` 的组成部分，`DEC-057` 冻结基准时按此范围执行。

- **A 级**（适用第 10 节的像素与几何阈值）：`01` 第 10 节点名的九类页面——首页四视图、版块页、主题详情、登录/注册、用户主页、设置、举报入口、静态政策页、授权 `/manage` 首页。
- **B 级**（只做结构级检查，不做逐像素比对）：其余页面与全部错误态，检查项为无横向溢出、触控目标不小于 44px、对比度达标、键盘可达、无 JavaScript 可用、错误态可达。

MVP 至少覆盖：

- 首页四种视图。
- 版块页、标签页和搜索页。
- 主题详情、回复和编辑页。
- 登录、注册、验证、找回和重置密码。
- 新用户引导。
- 用户主页和四个“我的”集合页。
- 偏好、隐私、资料、会话和邀请设置。
- 举报、反馈、客服和静态政策页。
- 授权与未授权 `/manage` 核心页面。
- 400、401、403、404、409、428、429、503 错误态。

## 7. 组件范围

- 顶部品牌栏、桌面导航和移动抽屉。
- 搜索框、主题模式、语言和账号入口。
- 版块胶囊、排序导航、主题行和分页。
- 头像、标签、状态标记和计数。
- 按钮、图标按钮、输入、选择、复选框和表格。
- 卡片、提示、空状态、错误状态和确认对话框。
- Markdown 工具栏、附件状态和上传进度。
- 管理队列、筛选器、敏感数据提示和审批状态。

页面 section 不做浮动卡片堆叠；卡片只用于重复项目、模态框和确有边界的工具。

## 8. 响应式合同

### 768px 及以上

- 桌面品牌栏、导航、搜索和右栏按基准布局。
- 主内容与右栏宽度稳定，长标题换行但不挤压计数列。

### 760px 临界点

- 明确切换到移动结构，不出现桌面和移动控件同时占位。
- 抽屉入口、搜索、发布和账号入口均可达。

### 390px 与 320px

- 单栏列表、可滚动或换行的版块胶囊；移动首页隐藏访客、热门和最新侧栏卡，统计卡移至列表下方保留（`DEC-043` 当前实测），不再统一隐藏右栏所有内容。
- 搜索、表单、编辑器和管理操作不产生页面级横向溢出。
- A00 先冻结当前参考控件几何；参考站不足 44x44 CSS px 的触控目标逐组件登记，不擅自增大而改变外观（`DEC-043`）。E04 仍检查触控目标、WCAG 与必要的无障碍差异。
- 最长中文/英文 token 不遮挡相邻内容。

## 9. 无障碍

- 目标为 WCAG 2.2 AA。
- 本轮 A00 的开发期几何采集服从 `DEC-043`；参考站存在的触控目标或对比度问题如实登记为 E04 待验项，不能据复制完成宣称 WCAG 通过。
- 唯一且可跳转的主内容区域。
- 完整语义标题、label、错误关联和 live region。
- 所有功能可键盘操作，焦点可见且顺序合理。
- 颜色对比度、状态非纯颜色表达、减少动态效果和高缩放可用。
- 图标按钮有可访问名称和必要 tooltip。
- 无 JavaScript 时浏览、分页、登录跳转和关键表单仍可工作。

## 10. 差异门禁

本门禁在统一硬化阶段集中执行（`DEC-020`）；阈值本身不随验证分层放宽。

本表只适用第 6 节的 A 级页面。**比较对象**必须分开：像素差异一律对 `visual-baseline-v1` 实现基准做回归（防止实现漂移），几何差异对参考站截图做比对（验证复制精度）。二者不可混用——品牌文字已按本项目替换为“草莓论坛”，对参考截图做像素比对在页头区域永远不可能达到 0.5%。

| 范围 | 像素差异（对实现基准） | 几何差异（对参考截图） |
|---|---:|---:|
| Logo、品牌文字、页头 | `<= 0.5%` | `<= 2px` |
| 核心组件 | `<= 1%` | `<= 2px` |
| 整页静态外壳 | `<= 2%` | `<= 2px` |

具名例外（按第 1 节格式登记原因与批准人）：品牌文字由“草莓论坛”替换、六个自定版块名称导致的文字盒模型宽度差异，不计入几何差异；例外范围仅限这两项，不得扩展。

导航条目为**六项**（`DEC-068`）。项目所有者明确这不是冻结例外：基准本身按六项更新，不在冻结之上挂豁免。因此参考站四项导航与本站六项之间的条目数差异，属于基准差异而非待修偏差，不得据此判失败；条目数以外的品牌栏几何、间距与响应式行为仍按本节阈值比对。

禁止通过降低截图倍率、放宽阈值、改变浏览器/字体或删除断言获得通过。遮罩范围按第 11 节执行：用户生成内容可遮罩，品牌标识、页头、导航、搜索入口与被测组件的几何边界不可遮罩（`DEC-037`）。

## 11. 遮罩规则

遮罩规则在统一硬化阶段的差异验证中适用（`DEC-020`）。

本轮开发采集按 `DEC-044` 保存原始截图到 Git 忽略的本地证据目录，由用户负责后续脱敏；Codex 不再强制截图前遮罩，且按用户后续指令移除已生成的脱敏参考截图并重新截图。以下白名单和坐标冻结要求仍适用于最终要公开或用于正式基准的截图，不以原始本地截图替代正式批准。

**可遮罩**（`DEC-037`）：全部用户生成内容与随时间变化的数据——帖子正文、主题标题、列表文字、用户名、用户简介、头像、时间戳与各类计数。参考截图正是因为这些内容才无法脱敏入库，扩大白名单是让脱敏后的截图可以版本化的前提。

**不可遮罩**：品牌标识、品牌文字、页头、导航、搜索入口，以及被测组件自身的几何边界（卡片外框、按钮盒模型、间距与颜色）。遮罩不得用来掩盖这些元素的差异——那正是门禁要测的东西。

所有遮罩必须记录矩形坐标、原因与审批，遮罩清单随基准一并冻结并版本化；变更遮罩清单等于变更基准，需重新冻结。

## 12. 验证流程

本流程在统一硬化阶段集中执行（`DEC-020`）。

1. 校验资产清单和文件哈希。
2. 启动最新构建与稳定数据库夹具。
3. 固定浏览器、字体、缩放、动画和时钟。
4. 捕获六视口乘两主题的页面矩阵。
5. 检查计算 token、几何、溢出、重叠和触控目标。
6. 执行键盘、移动抽屉、无 JavaScript、长文本和动态错误态。
7. 对实现基准执行像素回归，对参考截图执行第 5 节计算值与几何/间距/颜色比对，分别对照第 10 节两列阈值，生成 JSON 与 Markdown 报告。
8. 人工复核品牌、裁剪、隐私和异常差异。
9. 在 `99` 登记版本、命令、结果、SHA-256 和阻塞。
