# 10 M0：决策与可复现基线

状态：`In progress`（开发期；`WP-M0-01` 已完成计划与决策冻结，`WP-M0-03` 的技术与供应链配置、检查和边界见 `99` 第 5.2 节；`WP-M0-04` 数据/权限设计及独立复核已完成，映射、依赖和证据见 `99` 第5.4节；WP-M0-05容量模型/口径/生成方式和独立复核见99 §5.5；不据此授予 M0 整体或发布门禁）。

## 1. 范围

- 需求：`CAT-000`、`CAT-001`、`TRADE-000`、`TRADE-001`、`PRIV-000`、`PRIV-005`。
- 平台工作包：`WP-M0-01`、`WP-M0-02`、`WP-M0-03`、`WP-M0-04`、`WP-M0-05`、`WP-M0-06`。
- M0 不以源码数量为完成标准，而以决策、基准、责任和可验证工程约束为完成标准。

## 2. 执行顺序

1. 冻结需求集合、阶段映射、决策和冲突。
2. 批准视觉基准组合方式并冻结 `visual-baseline-v1`；组合方式已由 `DEC-057`（2026-09-06）批准，`DEC-019` 关闭。参考采集与本地化前移至 `WP-MVP-A00`（`DEC-021`），像素级验收在统一硬化阶段执行（`DEC-020`）。
3. 锁定工具链、数据库、Redis、搜索扩展和测试镜像。
4. 评审 schema、ACL、事务、Outbox、审计、保留和迁移设计。
5. 建立容量与性能基线模型（`WP-M0-05`，`DEC-036`）；[派生模型](../docs/design-notes/2026-09-capacity-baseline.md)已交付并完成开发期复核，证据见99 §5.5；实测基线与重验证在统一硬化阶段执行（`DEC-020`）。
6. 批准供应商、生产规格、法律边界和责任人。
7. 完成真实冷启动人员、排班和种子内容。

## 4. Production Approved 门禁

- [ ] 产品定位、首批流量来源和四版块负责人批准。
- [ ] 运营主体及适用备案、内容、隐私、未成年人、交易和促销要求批准。
- [ ] 交易允许品类、禁售清单、商家材料期限和审核责任人批准。
- [ ] 奖品边界批准；未批准则相关功能永久关闭。
- [ ] VPS 地域、规格、卷、连接池、配额和扩容阈值批准。
- [ ] SMTP、对象存储、验证码、错误追踪、密钥和搜索词典责任人确定。
- [ ] 发送域 SPF/DKIM/DMARC 认证记录配置完成并通过一次投递自检（阻塞于 `DEC-011`）。
- [ ] 审核、申诉、诈骗投诉、安全事件和灾难恢复责任人与排班确定。
- [ ] P1/P2 量化启用阈值确定。
- [ ] SiteOwner 权限、唯一 IAM registry、移帖跳转和密码泄露检查语义批准。
- [ ] `visual-baseline-v1` 正式批准。
- [ ] 3 至 5 名创始成员、2 名稳定答题者、1 名管理员、0 名版主和约 10 篇种子内容真实到位。

## 5. 退出规则

M0 Repository Ready 可以允许进入受控 MVP 开发，但不能允许公开测试。M0 Production Approved 未完成时，MVP 最多形成仓库发布候选，所有生产 Feature Flag 保持关闭。

双门禁制保持不变。重验证类退出条件——视觉像素差异验收、性能与容量实测基线、SBOM/secret/许可证扫描取证——按 `DEC-020` 在功能开发完成后的统一硬化阶段集中执行；开发期需求与工作包最高标记 `Implemented`。
