# 03 `/manage` 管理后台

## 1. 目标与边界

`/manage` 是草莓社区唯一管理入口，服务于治理、客服、风险、隐私、运行和审计。它不是普通用户页面的隐藏模式，也不是绕过领域权限的数据库工具。

MVP 只开放已列入本文件的路由。后续阶段页面可以有关闭状态下的导航定义和数据结构，但服务端必须返回 `404` 或明确不可用，不能只依赖前端隐藏。

## 2. 路由地图

| 路由 | MVP 用途 | 最低能力 |
|---|---|---|
| `/manage/login` | 独立管理登录 | 有效 staff principal + MFA |
| `/manage/session/reauth` | 高危重新认证 | 当前管理会话 |
| `/manage` | 工作队列与健康摘要 | 按角色裁剪 |
| `/manage/users` | 用户查询、状态和限制 | `iam.users.read/write` |
| `/manage/content` | 内容、版块、标签和治理动作 | `community.content.*` |
| `/manage/reports` | 举报队列和证据 | `moderation.reports.*` |
| `/manage/cases` | 案件、处罚和申诉 | `moderation.cases/appeals.*` |
| `/manage/support` | 客服和账号恢复 | `support.*` |
| `/manage/privacy` | 隐私请求和删除执行 | `privacy.requests.*` |
| `/manage/invites` | 邀请创建、冻结、撤销和查询 | `trust.invites.*` |
| `/manage/config` | MVP 配置和 Feature Flag | `operations.config.*` |
| `/manage/jobs` | Outbox、DLQ、邮件、媒体和搜索任务 | `operations.jobs.read` |
| `/manage/analytics` | 脱敏运营与社区健康 | `analytics.*` |
| `/manage/audit` | 审计查询 | `audit.*` |
| `/manage/approvals` | 高危申请和审批 | `iam.approvals.*` |
| `/manage/system` | 健康与事故 | `operations.health.*` |

所有数据端点使用 `/manage/_api/v1/` 前缀，并与页面采用同一服务端授权路径。

## 3. 角色原则

候选角色包括版主、全局版主、客服、风控运营、活动运营、管理员、站点所有者和只读审计员。机器可读角色名、权限集合和配置键由仓库内单一 TOML registry 文件生成，构建期同时产出 Rust 枚举与数据库种子，三者不一致时启动拒绝（`DEC-058`，关闭 `DEC-018`／`CR-013`）。

SiteOwner 权限集已固定为四类极高危运维（`DEC-058`，关闭 `DEC-016`／`CR-011`）：密钥轮换、账单与供应商、生产访问授权、灾备恢复。不含任何内容、用户、审核或客服日常权限，禁止 `all permissions` 通配，也不包含紧急内容下架；需要紧急下架时走管理员与审批链，不绕过职责分离。

下列最低边界继续全部有效：

- 一名用户同一管理会话只能激活一个角色。
- SiteOwner 不默认拥有日常社区权限。
- 客服不能直接处罚、改账本、关闭 MFA 或读取无关证据。
- 版主只能处理授权版块或案件范围。
- 风控运营不能编辑内容正文或账本。
- 活动运营不能审批本人活动或选择中奖者。
- 只读审计员没有生产写权限。
- 管理员也不能删除审计、读取明文 secret 或自批高危操作。

## 4. 授权模型

每次请求重新从 PostgreSQL 读取并校验：

1. 用户生命周期状态。
2. staff principal 是否 active。
3. 管理会话未撤销、未过期、未空闲超时。
4. 角色分配的开始、到期、撤销和版本。
5. 当前 authz version 与会话版本一致。
6. 角色和权限都在闭合 registry 中。
7. 权限与资源类型匹配。
8. ABAC 范围覆盖目标资源及其当前关系。
9. MFA 和适用的重新认证有效。
10. 适用审批已通过且操作者不是自己的审批人。

客户端提供的角色名、权限布尔值、目标关系、对象状态、批量数量和审批结果均不可信。

## 5. ABAC 范围

支持 `global`、`forums`、`case`、`ticket`、`environment` 等范围。范围记录包含类型、资源 ID 集合、开始、到期和版本。

- 数字 ID 必须同时携带资源类型，防止同值 ID 跨域复用。
- 版块范围通过目标内容当前 `forum_id` 验证。
- 案件、举报、证据和申诉必须验证父子关系。
- 客服工单、账号恢复和用户必须验证工单目标绑定。
- 范围变更、到期和撤销必须在最终写入事务内重新读取。

## 6. 会话与 MFA

- 管理登录与普通用户登录使用独立 cookie 和路径。
- 管理会话最长 8 小时，空闲 15 分钟。
- 高危操作要求 5 分钟内重新认证。
- MFA assertion 单次消费、绑定用户/会话/用途、短时过期。
- 恢复码只显示一次并只存哈希。
- MFA 恢复需要身份核验和两名授权人员复核，客服不能单独完成。
- break-glass 最长 30 分钟，需要即时告警和事后复盘；不等同于 P2 生产 JIT。

## 7. 审批和职责分离

下列操作至少需要双人或明确的高危审批策略：

- 特权角色授予、权限扩大和 MFA 恢复。
- 大范围内容处置或批量用户限制。
- 隐私删除执行、法律保留变更和敏感导出。
- 生产 Feature Flag、高风险配置和 break-glass。
- 后续阶段的积分、商家、活动、抽奖和开放集成。

申请人、目标操作者和审批人关系由服务端验证。同一人不得自提自批，撤销批准不能继续执行旧操作。

## 8. 敏感数据

| 级别 | 后台行为 |
|---|---|
| C0 | 可按公开规则展示 |
| C1 | 最小字段展示 |
| C2 | 逐次授权、用途和理由 |
| C3 | 永不由 API 或页面返回，只允许专用验证结果 |

列表接口不能为了方便携带详情敏感字段。下载授权为短时单次 token：有效期 60 秒，绑定用户、管理会话与目标对象，单次消费；文件响应必须 `private, no-store`，并在下载时重新授权。本节是该参数的事实源，`90` 只引用不定义。

## 9. 写命令合同

管理写请求必须包含：

- CSRF token。
- 幂等键。
- 目标资源类型和 ID。
- 期望资源版本或 `If-Match`。
- 理由代码和必要说明。
- 工单/案件关联。
- 高危操作的重新认证和审批引用。

命令在一个事务内提交目标状态、版本、操作日志、幂等结果和 Outbox。响应不得在未知提交状态下声称成功。

## 10. 批量操作

- 单批最大 100 个目标。
- 超过 20 个目标由 Worker 分块执行。
- 每个目标独立记录状态、版本、结果和失败原因。
- 批量权限按每个目标重新验证，不能只检查列表入口。
- 重放不能重复处罚、重复通知或跳过失败目标。
- 取消只停止未开始部分，不回滚已提交事实。

## 11. 页面交互

- 任务优先、信息密度高、避免营销式布局。
- 表格支持键盘、明确排序、筛选、分页和空/错/加载状态。
- 高危按钮使用图标和清晰命令名，破坏性操作需要确认与理由。
- 不在前端缓存 C2/C3 数据，不把敏感字段写入 URL。
- 直接 URL、替换 ID、旧标签页、并发修改和过期会话都有服务端拒绝证据。
- `/manage` 复用公共品牌资产、token 和组件外观，但信息架构以本项目需求为准，不臆造参考站后台。

## 12. MVP 验收

本节验收要求内容不变；按 DEC-020 验证分层，统一在功能开发完成后的发布前硬化阶段集中执行，开发期需求与工作包最高标记 `Implemented`，`Verified` 及以上状态只能在硬化阶段凭证据授予。

- 每个 MVP 路由都有允许、无角色、错误角色、错误范围、对象状态错误、ID 替换、过期会话、旧权限版本、缺 MFA、缺重新认证和缺审批测试。
- 角色权限矩阵由同一个机器 registry 生成并与数据库种子、配置、文档一致。
- C3 字段静态和运行扫描为零泄露。
- 关键拒绝路径有服务端拒绝证据。
- 批量边界、幂等、并发更新和 Worker 分块通过真实 PostgreSQL 测试。
- 授权后台完成桌面、移动、明暗主题、键盘和无 JavaScript 浏览器验证。
- 所有后续阶段 section 服务端不可达，Feature Flag 关闭。
