# 90 质量、验证与发布门禁

## 1. 原则

- 验证分两层（`DEC-020`）：开发期每次代码检查点只执行最小集（第 4 节）；功能开发完成后的统一硬化阶段集中执行完整测试矩阵与证据扫描（第 5 节）。
- 测试规模与风险匹配。
- 关键安全、事务、权限和恢复路径的完整验证在统一硬化阶段执行，不得只凭开发期最小集宣称通过。
- 幂等、事务边界、Outbox 同事务提交、版本防覆盖是开发期就必须遵守的设计纪律，靠代码审查与单元测试保障，不靠后期补；Feature Flag 默认全关且后续能力路由服务端不可达、公开仓库脱敏同属设计纪律，不随验证后置而放松（`DEC-020`）。
- 开发期需求与工作包最高标记 `Implemented`；`Verified`、`Release candidate`、`Released` 只能在统一硬化阶段凭证据授予（状态模型见 `README.md` 第 6 节，`DEC-020`）。
- 失败必须修复根因，不得跳过测试、删除断言、放宽阈值或伪造证据。
- 只有当前候选版本的证据可以支持 `Verified` 或发布门禁。
- 完整模式数据库测试使用真实 PostgreSQL 16，并同时验证默认 `bcm_` 与随机非默认前缀；体验模式使用真实 SQLite（WAL）跑核心流程（属统一硬化阶段；开发期最小集只含 SQLite 冒烟）。
- Redis 合同使用真实 Redis 8（属统一硬化阶段）。
- 页面使用真实浏览器验证，不以模板字符串断言替代视觉和交互证据（属统一硬化阶段）。

## 2. 证据包结构

证据包与第 3 节逐需求 8 字段证据在统一硬化阶段（`DEC-020`）补齐；开发期只在 `99` 登记工作包级状态与阻塞。

每个工作包在 `docs/evidence/<phase>/<work-package>/<candidate>/` 保存可公开的证据清单：

```text
manifest.json
summary.md
commands.txt
tests/
security/
performance/
recovery/
visual/
```

`manifest.json` 至少包含：

- commit、toolchain、lockfile、迁移最高版本和配置 schema 版本。
- 测试环境指纹和依赖版本。
- 执行命令、开始/结束时间、退出码和日志 SHA-256。
- Feature Flag 快照。
- 需求 ID、工作包、结果和已知限制。
- 证据文件路径、是否脱敏及公开安全结论。

临时路径、截图数量或口头描述不能单独作为证据。未经脱敏的截图、profile、数据库 dump、Cookie 和 secret 不入库。

## 3. 单项需求证据

本节 8 字段证据与第 2 节证据包同步在统一硬化阶段（`DEC-020`）补齐；开发期只在 `99` 登记工作包级状态与阻塞。

每个需求至少追踪：

| 字段 | 内容 |
|---|---|
| Requirement | 精确 ID 和原文 |
| Deliverable | 代码、配置、迁移、资产或手册版本 |
| Interface | 页面、API、命令或事件 |
| Data | schema、表、索引、保留和迁移 |
| Authorization | 角色、范围、状态、会话、MFA 和审批 |
| Atomicity | 锁、版本、幂等和 Outbox |
| Tests | 单元、集成、E2E、安全、并发、性能和视觉 |
| Evidence | 当前证据 manifest |

## 4. 开发期最小集

开发期每次代码检查点只执行（`DEC-020`）：

统一入口为 `scripts/dev-check.sh`（`WP-MVP-A01` 交付），内容与顺序如下，任一步失败即中止：

1. `cargo fmt --all -- --check`。
2. `cargo clippy --workspace --all-targets --locked -- -D warnings`。
3. `cargo test --workspace --locked`（含共享 SQL lint，见 `02` §6.1 语义差异禁用清单）。
4. **SQLite 冒烟**：以 `BBBCM_CONFIG` 指向临时配置与临时 `sqlite_path`，执行 `bbbcm-cli db migrate --backend sqlite`（`WP-MVP-A03` 接入后生效），启动 `bbbcm-web`，对 `scripts/smoke-routes.txt` 逐行 `curl` 断言状态码，退出前删除临时库。每个工作包退出时把本包新增路由追加进该清单——这是「核心流程可用」的可执行定义。
5. `git diff --check`（行尾空白与冲突标记）。
6. 打印 `git diff --cached --name-only` 供人工复核；若同一次暂存同时包含 `plan/06` 与 `crates/`｜`apps/` 路径则告警（`06` 第 5 节要求决策单独提交）。
7. 静态守卫：`git grep -n sqlx -- 'crates/*/src/http.rs' 'apps/web/src'` 必须为空（`02` §2.1 禁止 handler 直接写 SQL）；扫描暂存内容中的真实域名、生产端口与内网地址。

各工作包退出条款中的「（适用时）」判定：本工作包新增或修改了迁移、路由或模板时，第 4 步（SQLite 冒烟）适用；否则跳过并在提交说明写明原因。

最小集**不含独立的构建步**（`DEC-039`，回到 `DEC-020` 原文）：Clippy 与测试本就要编译整个工作区，单列一步不增加覆盖面。

真实 PostgreSQL/Redis 集成、全 feature/target 构建、安全套件、性能与证据扫描不在每次检查点执行，统一进入第 5 节硬化阶段；最小集不降低第 1 节设计纪律要求，相关纪律靠代码审查与单元测试保障。

### 4.1 证据失效范围

硬化阶段的证据绑定当前 commit，但并非任何改动都作废全部证据。按变更类型限定重跑面，避免每次改动都要重跑整个矩阵：

| 变更类型 | 作废的证据 |
|---|---|
| 迁移、方言分支、`platform-*` | PostgreSQL 集成、SQLite 体验模式、并发、性能 |
| 模板、CSS、静态资产 | `05` 第 10 节对应页面与组件的视觉证据（仅受影响页面） |
| 权限 registry、ABAC 范围 | 安全套件与 `03` 第 12 节授权矩阵 |
| 领域 `core`/`repo` | 该领域的单元与集成证据，以及依赖它的 E2E |
| 仅文档、注释、`plan/` | 不作废任何运行证据 |

未列入的改动只重跑受影响工作包的证据。作废判定与重跑结果在 `99` 登记。

## 5. 统一硬化阶段

功能开发完成后集中执行（MVP 为 E 段工作包，`DEC-020`）。发布候选须执行全工作区、全部 feature/target 构建，以及 E2E、安全、并发、性能、恢复、无障碍和视觉矩阵；数据库按多后端矩阵（PostgreSQL/SQLite，MySQL 8.0 接入后纳入，`DEC-022`）覆盖；并产出证据 manifest、SBOM、secret 与许可证扫描。

本节全部适用条目通过且证据齐备后，需求与工作包方可授予 `Verified` 及以上状态。

### 单元加强

- 领域状态机、输入边界、Markdown 清洗和序列化。
- 权限 registry、角色能力、scope 和审批规则。
- 邀请、资格、限额、密码、会话、隐私和删除规则。
- Outbox 重试、退避、sink 状态和错误分类。
- 后续阶段的账本、活动和随机规则在对应阶段测试。

### PostgreSQL 集成

- 空库迁移、重复运行、checksum 和 advisory lock。
- 默认/非默认 schema、受信标识符渲染和 bind 参数。
- 唯一/检查/外键/触发器、ACL 和未来对象默认权限。
- 事务回滚、未知提交、同/异载荷幂等、版本冲突。
- `40001/40P01` 可控重试和固定锁顺序。
- Outbox、审计、搜索权限状态与业务事实同事务。

### Redis 集成

- `bcm:<environment>:v1:` namespace（仅 `features.redis=true` 时装配；关闭时验证缓存回退进程内存、且限流能力不存在——按 `DEC-024` 体验模式无限流，须断言高风险端点不因缺少限流而报错，也不伪装成已限流）。
- token bucket 原子性、TTL、Redis `TIME` 和失败模式；Redis 已启用但不可用时，注册、登录、找回与举报等高风险写失败关闭，公开读仍可回源 PostgreSQL。
- lease、唤醒和缓存可丢失性。
- `SCAN + UNLINK` 只清理当前环境，清理后从 PostgreSQL 重建。

### SQLite 体验模式

- WAL、busy_timeout、外键与连接池行为验证。
- 核心流程：注册、登录、发帖、回复、标题搜索、举报、基础后台。
- FTS5 探测与 LIKE 降级断言；正文搜索入口返回受限提示而非错误。
- 迁移 N 轨编号对齐校验（`DEC-022`）。

### HTTP/E2E

- 成功、空、错误、未认证、未授权、冲突、过期和依赖失败。
- CSRF、Cookie、CSP、缓存、下载和安全响应头。
- JavaScript 开启/关闭、刷新、返回、重试和多标签页。
- 桌面和移动真实浏览器。

### 安全

- XSS、CSRF、SQL 注入、SSRF、开放重定向和点击劫持。
- 枚举、时序、凭证填充、限速和验证码边界。
- 水平/垂直越权、ID 替换、scope 混淆、旧权限版本和自批。
- 上传 MIME、文件头、压缩炸弹、像素炸弹、恶意内容和下载鉴权。
- 日志、错误、HTML、JSON、XML、Feed、OG、分析和审计敏感泄露。
- 依赖、许可证、Secret、SBOM、容器和 IaC。

供应链工具及可重复入口由 `WP-M0-03` 锁定在 `supply-chain/lock.json`、`supply-chain/{syft,trivy}.yaml`、
`supply-chain/gitleaks.toml` 和 `scripts/supply-chain-scan.py`，操作说明见 `supply-chain/README.md`。
E01 使用干净候选生成含 Cargo/npm dev/optional 与扩展源码的 SBOM，并扫描实际服务镜像；许可证清单须保留未知项及 A00 原资产登记，扫描执行成功不能代替许可审核。
漏洞库按候选刷新后离线复用，记录实际数据库文件摘要；全部严重度与无修复项保留，Critical/High 返回失败。Secret 扫描覆盖 Git 全历史，报告强制脱敏。
开发期仅对本轮基线做一致性、合成小夹具与暂存区检查，不向 `dev-check` 增加全量扫描或独立构建（`DEC-020/039`）。

### 并发

MVP：邀请码消费/额度、邮箱验证、密码恢复、主题楼层、互动唯一性、举报合并、治理命令、Outbox lease 和通知去重。

P1-A：积分、签到、投票、悬赏和邀请奖励各 1,000 路。

P2：抽奖、红包、兑换码、预算冻结和开奖各 1,000 路。

后续阶段测试不阻塞 MVP，但对应 Feature Flag 和路由关闭测试必须阻塞 MVP。

### 搜索

- 中文相关性、简繁、短语、标题、正文、用户名、版块和标签。
- 权限、拉黑、待审、删除、隐藏和版块关闭过滤。
- 签名游标和插入并发下无重复/漏项。
- 100 万内容重建、查询 p95 和收紧传播。

### 浏览器与视觉

- `1440/1024/768/760/390/320px`。
- light/dark/system。
- 键盘、可见焦点、44px 触控、无 JS、长文本和错误态。
- WCAG 2.2 AA。
- 资产 SHA-256、计算样式、几何和 0.5%/1%/2% 像素差异——仅适用 `05` 第 6 节的 A 级页面，且像素对实现基准、几何对参考截图（`05` 第 10 节）；B 级页面只做结构级检查。

## 6. 固定性能指标

本节门槛的达标验证属统一硬化阶段（`DEC-020`），开发期最小集不逐次执行。

| 指标 | 门槛 |
|---|---|
| 注册用户 | 10,000 基线 |
| 主题与回复 | 1,000,000 基线 |
| 峰值在线 | 300 |
| 公开读负载 | 200 read/s 起点 |
| 写负载 | 20 write/s 起点 |
| 公开读 p95 | <=400ms |
| 写 p95 | <=800ms |
| SSR 首屏 p95 | <=800ms |
| 管理批量 | 最大 100，超过 20 由 Worker 分块 |
| 管理会话 | 最长 8 小时，空闲 15 分钟 |
| 高危重新认证 | 5 分钟内 |
| 证据下载授权 | 60 秒（定义见 `03` 第 8 节，本表只引用） |
| 删除/隐藏/权限收紧向搜索与缓存的传播 | <=60 秒（`DEC-030`） |
| 邮箱验证令牌有效期 | 24 小时，单次消费（`DEC-030`） |
| 密码重置令牌有效期 | 1 小时，单次消费（`DEC-030`） |
| 普通用户会话 | 绝对上限 30 天，滑动续期 14 天（`DEC-030`） |
| 用户名修改冷却期 | 30 天；历史用户名保留 90 天（`DEC-030`） |
| T0 新用户限速 | 每日 5 主题 / 20 回复；注册后 24 小时内 1 主题 / 5 回复（`DEC-030`） |
| 申诉受理期限 | 处罚生效后 30 天内可提起，受理后 7 天内出结论（`DEC-030`） |

测试报告必须说明地区、设备、缓存冷热、连接池、数据分布、测量窗口和资源规格。规格未批准时只能形成实验结果，不能支持 Production Approved。

## 8. 缺陷与例外

- Critical/High 在公开测试前必须为零。
- 例外必须记录影响、补偿措施、负责人、到期日和关闭条件。
- Medium/Low 必须进入有期限 backlog，不能从报告删除。
- 视觉阈值、权限拒绝和数据不变量不接受口头豁免。
