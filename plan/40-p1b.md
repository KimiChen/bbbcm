# 40 P1-B：商业供给

状态：`Not started`，MVP 期间全部 Feature Flag 关闭。

## 1. 进入条件

分两组，不可混淆：**开发进入条件**决定能否开始编码，**启用与排期条件**决定能否对用户开放。`DEC-014` 属后者——阈值未达成不阻塞开发，只阻塞排期与启用（`04` 第 9 节）。全程 Feature Flag 关闭且服务端路由不可达。

- MVP 已 Released；不强制等待 P1-A 全部启用。
- 交易地区、允许品类、禁售清单、运营主体和适用法律已批准。
- 商家材料保留期限、审核责任人、利益冲突和申诉流程已批准。
- 共用 IAM、审计、风控、客服、隐私和恢复底座已 Verified。
- `DEC-014` 的 P1-B 量化阈值已达到。

## 2. 范围

- 18 个 P1-B 需求。
- 通用 P1 中归入本阶段的 ID：`USER-105`、`ADMIN-103`、`DATA-104`。
- 商家认证、结构化交易/优惠、披露、投诉、评价和商业分析。
- 不提供站内支付、托管资金、平台担保、充值提现或资金裁决。

## 3. 工作包

### `WP-P1B-01` 商家认证

需求：`USER-105`、`MERCHANT-101` 至 `MERCHANT-107`、`ADMIN-103`。

材料加密、人工核验、授权代表、官方渠道控制、认证范围、到期复审、冲突披露、暂停、撤销和申诉。系统不做自动外部核验。

### `WP-P1B-02` 交易与优惠内容

需求：`TRADE-101` 至 `TRADE-106`。

结构化价格、库存、有效期、地域、关键条款历史、推广披露和自动过期。外链使用安全跳转和明确责任提示。

### `WP-P1B-03` 投诉与评价

需求：`TRADE-107/108`。

投诉证据、商家响应、处理状态、评价资格和异常互评复核。处罚和认证状态在搜索、列表和详情一致传播。

### `WP-P1B-04` 商业分析

需求：`DATA-104`。

曝光、点击、投诉、解决率和认证健康指标，与内容质量及活动流量分离。只使用脱敏、版本化事件字典。

## 4. 退出门禁

阶段内开发期每次提交只执行 `DEC-020` 最小集；以下门禁项在该阶段的统一硬化环节集中验证，通过前不授予 `Verified` 及以上状态。

- [ ] 18 个需求均达到符合事实的 Implemented/Verified。
- [ ] 材料加密、保留、删除、C2/C3 权限和逐次查看审计通过。
- [ ] 利益冲突、双人复核、暂停、撤销、标识失效和越权测试通过。
- [ ] 禁售、地域、有效期、投诉和响应 SLA 已批准并可执行。
- [ ] 搜索、Feed、分享和分析不泄露商家材料或联系方式。
- [ ] 所有支付、托管、担保和资金裁决路径保持不可达。
- [ ] P1-B 可独立关闭且不破坏 MVP/P1-A。
