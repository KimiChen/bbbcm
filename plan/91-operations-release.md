# 91 运维、恢复与发布

## 1. 环境

| 环境 | 目的 | 数据规则 | Feature Flag |
|---|---|---|---|
| development | 本地开发 | 合成数据 | 可显式开启 MVP demo，后续关闭 |
| test | 自动验证 | 每次隔离的合成数据 | 测试显式控制 |
| staging | 发布候选验证 | 脱敏或合成生产规模数据 | 与拟发布生产快照一致 |
| production | 真实服务 | 受批准保留和访问策略约束 | 默认关闭，审批后逐项开启 |

不得把开发数据库、浏览器 profile、`.env`、测试密钥或未脱敏截图带入生产或版本库。

完整测试矩阵与证据包在统一硬化阶段（`DEC-020`，见 `90` 第 5 节）集中产出；development 与 test 环境的日常检查点只执行开发期最小集（`90` 第 4 节），staging 复核硬化阶段证据与当前候选快照。

## 2. 生产拓扑

已批准方向为 Cloudflare 前置、单 VPS 和 PostgreSQL 单主。以下值必须在 `DEC-004-B/011/013` 中批准后填写：

- 地域、实例规格、磁盘和独立持久卷。
- PostgreSQL 内存、连接池和 autovacuum 参数。
- Redis 部署和内存上限。
- 对象存储供应商与地域。
- SMTP、验证码、错误追踪和密钥服务。
- 月度预算、资源配额和扩容阈值。

计划不提供猜测默认值。

## 3. 发布工件

每个候选冻结：

- Git commit 和签名/来源信息。
- Rust toolchain 与 `Cargo.lock`。
- 迁移 N 轨集合和最高版本（`DEC-022`）。
- 配置 schema、脱敏模板和 Feature Flag 快照。
- 静态资产 manifest 和品牌资产哈希。

## 4. 发布前顺序

1. 确认 M0/MVP Repository Ready 和 Production Approved。
2. 冻结需求、commit、迁移、配置和 flag。
3. 验证数据库、Redis、对象和邮件依赖可用。
4. 确认发送域 SPF/DKIM/DMARC 记录生效并完成一次投递自检（`INTEG-005` 运维面，阻塞于 `DEC-011`）。
4. 运行 staging 全量回归、安全和视觉检查；完整测试矩阵证据在统一硬化阶段产出（`DEC-020`，见 `90` 第 5 节），本步为候选复核而非替代硬化验证。
5. 暂停不应发生的外部副作用并确认 DLQ 为空或已解释。
6. 完成 go/no-go 决定。

## 5. 应用发布

- 先部署关闭状态的新代码。
- 验证 liveness、readiness、数据库/Redis/对象/邮件依赖和关键 SSR。
- 保持注册、高风险写和后续阶段能力关闭。
- 按 `public_read -> search/feed -> auth -> content -> interaction -> governance -> manage` 顺序灰度。
- 每一步观察错误率、p95、数据库池、锁、Outbox 和 DLQ。
- 异常优先关闭能力或进入只读。

## 6. 上线与观察期

- 首次公开测试采用小流量、邀请制和可立即关闭的灰度。
- 观察业务错误、举报、垃圾注册、邮件投递、数据库、Outbox 和性能。
- 观察期长度和退出阈值需在 go/no-go 时批准，不能在本计划中猜测。
- 需求的 `Verified` 与 `Release candidate` 只能在统一硬化阶段凭证据授予（`DEC-020`）；观察完成后才能把需求从 Release candidate 更新为 Released。

## 7. 备份与恢复

规范见 `02` 第 18.1 节，本节记录待批准的运行值与操作要求：

- 备份方式、频率、保留期、加密与异地副本的具体取值待 `DEC-004-B` 批准，计划不填猜测默认值。
- 每个发布候选执行一次「从备份恢复到可服务」的完整演练并留存证据；未演练的备份不计入 Repository Ready。
- 恢复后第一件事是重放删除墓碑与法律保留状态，再开放流量，否则已删除数据会随恢复复活（`PRIV-007`）。
- 恢复演练的证据与发布工件一同冻结（第 3 节）。

## 8. 禁止动作

- 未经明确授权不 push、不部署、不购买服务、不创建真实外部账号。
- 不在命令、日志、证据或提交中记录真实密钥和生产地址。
- 不把单 VPS 描述为高可用。
- 不在未完成法律、责任和供应商决策时开放真实用户流量。
