## 2. 范围

- 28 个 P2 需求。
- 抽奖、红包、兑换码、高级商业、复杂团伙风控和生产 JIT。
- 每一类能力独立设计、验收、开关和发布，不能整包默认开启。

## 3. 工作包

### `WP-P2-01` 活动规则与预算

需求：`ADMIN-104`、`LOTTERY-201` 至 `LOTTERY-206`、`LOTTERY-210/212/214`。

版本化规则、时区、资格快照、地域/年龄限制、预算冻结、取消退款、奖品库存、交付和未领奖处理。

### `WP-P2-02` 可验证随机

需求：`LOTTERY-208/209/211/213`。

使用密码学安全随机、熵预承诺、候选集合哈希、算法版本、结果披露和可重放审计。管理员不能手选或覆盖结果。

### `WP-P2-03` 红包与兑换码

需求：`LOTTERY-207`、`REDPACKET-201` 至 `REDPACKET-207`。

唯一领取、行锁、份额结算、未领退款和反刷；兑换码加密且只向获奖者短时展示，日志和审计摘要无明文。

### `WP-P2-04` 高级商业

需求：`MERCHANT-201/202`、`TRADE-201/202`。

商家团队、明确标记的赞助位和外部订单只读同步，分别接受权限、隐私、成本和故障评审。

### `WP-P2-05` 复杂风险

需求：`RISK-201`。

团伙识别、关联信号、人工复核、误伤申诉、模型/规则版本和数据最小化。

### `WP-P2-06` 生产 JIT

需求：`RISK-202`。

临时提权、最短权限、双人批准、完整会话审计、自动到期和紧急撤销。MVP break-glass 不得被当作 JIT。
